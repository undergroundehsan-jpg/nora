\section{Non-Functional Requirements}

This section specifies the quality attributes that define how the AI Voice Reminder System performs, behaves, and maintains integrity under various operational conditions. These requirements ensure the system remains reliable, secure, scalable, and efficient throughout its lifecycle. All non-functional requirements are measurable, testable, and verifiable.
\subsection{Reliability}

Reliability defines the system’s ability to consistently perform automated reminder calls without unexpected failures or data loss.

\begin{itemize}
\item \textbf{REL-1:} The system shall maintain an uptime of at least 98\% during operational hours.
\item \textbf{REL-2:} The system shall automatically retry failed API calls (telephony, STT, TTS) up to three times before marking them as failed.
\item \textbf{REL-3:} The system shall log all service interruptions and maintain a Mean Time Between Failures (MTBF) greater than 250 hours.
\item \textbf{REL-4:} All scheduled reminders shall remain persistent even during server restarts using transactional database operations.
\item \textbf{REL-5:} Call session data shall be automatically saved in real time to prevent data loss during unexpected disconnections.
\end{itemize}
\subsection{Usability}

Usability ensures that administrators can easily manage reminder campaigns and monitor AI performance without extensive training.

\begin{itemize}
\item \textbf{USE-1:} A new administrator shall be able to schedule a reminder campaign within five minutes of first use.
\item \textbf{USE-2:} The dashboard shall provide tooltips and contextual guidance for all major features.
\item \textbf{USE-3:} The system shall provide clear status indicators for call states (Completed, Failed, Escalated).
\item \textbf{USE-4:} The admin interface shall load within 3 seconds on a standard broadband connection.
\item \textbf{USE-5:} The system shall support responsive design for desktop and tablet devices.
\item \textbf{USE-6:} The interface shall follow WCAG 2.1 accessibility contrast standards.
\end{itemize}
\subsection{Performance}

Performance requirements define responsiveness, scalability, and processing efficiency of AI-driven calls.

\begin{itemize}
\item \textbf{PER-1:} 95\% of outbound calls shall be initiated within 2 seconds of scheduled time.
\item \textbf{PER-2:} The system shall support at least 200 concurrent active calls without performance degradation.
\item \textbf{PER-3:} Speech-to-Text processing shall return transcriptions within 1 second of user speech completion.
\item \textbf{PER-4:} Text-to-Speech responses shall be generated within 1 second of response generation.
\item \textbf{PER-5:} Database read/write operations shall respond within 250 milliseconds under normal load.
\item \textbf{PER-6:} Call log retrieval queries shall return results within 2 seconds for datasets under 50,000 records.
\end{itemize}
\subsection{Security}

Security ensures confidentiality, integrity, and authenticity of user data and call sessions.

\begin{itemize}
\item \textbf{SEC-1:} All communication between client, server, and telephony APIs shall use HTTPS (TLS 1.3).
\item \textbf{SEC-2:} Administrator passwords shall be stored using salted hashing algorithms (bcrypt or Argon2).
\item \textbf{SEC-3:} The system shall implement Role-Based Access Control (RBAC) for admin privileges.
\item \textbf{SEC-4:} Sensitive data (customer details, transcripts, logs) shall be encrypted both in transit and at rest.
\item \textbf{SEC-5:} The system shall log all authentication attempts and flag suspicious login behavior.
\item \textbf{SEC-6:} API keys and environment credentials shall be stored securely using environment variables.
\item \textbf{SEC-7:} The system shall enforce rate limiting to prevent denial-of-service attacks.
\end{itemize}
\subsection{Maintainability}

Maintainability ensures ease of system updates, debugging, and AI model improvements.

\begin{itemize}
\item \textbf{MAI-1:} The system shall follow a modular architecture separating AI, telephony, database, and dashboard components.
\item \textbf{MAI-2:} All source code shall follow standardized linting and formatting rules.
\item \textbf{MAI-3:} Unit and integration test coverage shall exceed 80\%.
\item \textbf{MAI-4:} The CI/CD pipeline shall automatically test builds before deployment.
\item \textbf{MAI-5:} Configuration settings shall be externalized to allow updates without modifying source code.
\end{itemize}
\subsection{Scalability}

Scalability ensures the system can handle increasing call volume and user growth.

\begin{itemize}
\item \textbf{SCA-1:} The system architecture shall support horizontal scaling using cloud infrastructure (AWS or similar).
\item \textbf{SCA-2:} The database shall support at least 100,000 stored call records without performance degradation.
\item \textbf{SCA-3:} The system shall allow integration of additional AI voice models without architectural redesign.
\item \textbf{SCA-4:} Caching mechanisms shall be implemented to reduce repeated database queries.
\end{itemize}
\subsection{Portability}

Portability ensures that the system operates across multiple environments and deployment platforms.

\begin{itemize}
\item \textbf{POR-1:} The system shall be deployable on major cloud platforms (AWS, Azure, or Google Cloud).
\item \textbf{POR-2:} The application shall be containerized using Docker for environment consistency.
\item \textbf{POR-3:} The admin dashboard shall be browser-compatible (Chrome, Firefox, Edge, Safari).
\item \textbf{POR-4:} APIs shall follow RESTful standards to enable third-party integration.
\end{itemize}
\subsection{Availability}

Availability measures how consistently the system remains operational and accessible.

\begin{itemize}
\item \textbf{AVA-1:} The system shall maintain an availability rate of 99\% in production.
\item \textbf{AVA-2:} Scheduled maintenance shall not exceed 2 hours per month.
\item \textbf{AVA-3:} The system shall display a maintenance notification page during downtime.
\item \textbf{AVA-4:} Load balancing mechanisms shall ensure service continuity if one server instance fails.
\end{itemize}
